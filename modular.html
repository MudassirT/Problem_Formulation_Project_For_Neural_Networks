AI Problem Formulation Guide

Formal State-Space Search on Code Architecture

This laboratory models software architecture as a rigorous graph-theoretic state-space search problem. Every node represents an existing entity from the Point-of-Sale (POS) system (functions, classes, Django models, templates, unit tests), and every edge represents a verified structural relationship (calls, uses, contains, inherits, implements).

𝒫 = ⟨ S, A, T, s₀, G, c ⟩
  • Initial State (s₀): The agent's starting architectural focus in the application knowledge graph.
  • Action Space (A): Following existing relational links without inventing synthetic edges.
  • Goal State (G): Target architectural component satisfying the search predicate.
  • Cost Model (c): Semantic effort weights per relationship (e.g. calls=1, contains=4).
  • Why A* uses h(n)=0: On arbitrary topological knowledge graphs, geometric Euclidean distance on a 2D layout does not correlate with true remaining code traversal effort. An admissible heuristic h(n)=0 guarantees strict optimality equivalence with Uniform-Cost Search.
  • Alternative Routes: Yen's algorithm computes alternative loopless paths by systematically pruning spur paths.

Understanding AI State-Space Search & Code Architecture

In classical Artificial Intelligence (Russell & Norvig), any problem can be formally defined as a 6-tuple:

𝒫 = ⟨ S, A, T, s₀, G, c ⟩

S State Space

The set of all possible configurations. In this POS lab, every state is an actual code component: 349 entities (Django views, database models, HTML templates, and unit tests).

A Action Space

Valid operations the agent can perform. Here, an action is navigating along a verified architectural relationship (calls, uses, contains, inherits).

T Transition Model

Deterministic successor function: T(s, a) = s'. Moving across a transition changes active focus to the adjacent connected code entity.

s₀ Initial State

Where the agent begins navigation. For example, a user triggering a checkout HTTP request in sales_views_sales_add_view.

G Goal Test

A predicate verifying whether a state satisfies the objective. For example, verifying whether execution reaches sales_models_sale.

c Path Cost Function

c(path) = Σ c(e). Quantifies architectural traversal effort. Low friction for direct function calls (cost 1.0); higher friction for cross-module encapsulation (cost 4.0).

Compare how each search algorithm explores the state space and prioritizes paths:

UCS Uniform-Cost Search Optimal Cost Guaranteed

Priority: g(n) (accumulated path cost from start).

Expands nodes in strictly increasing order of cost. Guarantees finding the mathematically cheapest path for non-negative weights.

A* A* Search (Informed) Optimal Cost Heuristic

Priority: f(n) = g(n) + h(n).

On arbitrary software graphs, 2D coordinates do not reflect code dependencies. Using admissible h(n) = 0 guarantees strict optimal cost equivalence with UCS.

BFS Breadth-First Search Fewest Hops

Priority: Hop count (FIFO shallowest depth).

Explores all nodes at depth d before depth d+1. Guarantees finding the path with the fewest architectural transitions, ignoring edge weights.

DFS Depth-First Search Deep Traversal

Priority: Deepest unvisited path (LIFO stack).

Aggressively probes down a single branch before backtracking. Discovers reachability quickly, but often finds long, non-optimal paths.

State-space search maintains two key sets during execution:

🟣 The Frontier (Open Set)

A priority queue storing discovered nodes that have not yet been expanded. At every step, the node with the lowest priority value (cheapest g(n) or fewest hops) is popped from the queue.

🔷 The Visited Set (Closed Set)

Nodes whose outgoing edges have already been examined. Tracking visited states prevents infinite loops and cycles in graphs with bidirectional dependencies.

The Execution Lifecycle at Each Step:
  1. Pop node n with minimal priority f(n) from the Frontier queue.
  2. If n matches Goal State (G), terminate and reconstruct the optimal path backwards.
  3. Otherwise, add n to the Visited set (Closed Set).
  4. For each adjacent outgoing edge, compute successor state s' and its new cost g(s') = g(n) + c(e).
  5. If s' is not in Visited, insert or update it in the Frontier queue.
